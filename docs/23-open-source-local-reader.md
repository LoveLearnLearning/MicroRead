# 23. 开源本地 Reader 目标

> 状态：当前产品目标  
> 形态：独立开源、本地优先的 Web + Desktop 阅读器

## 1. 产品定义

阅微 / MicroRead 是一个证据优先的本地阅读工具。用户导入自己的 PDF 或公开网页，在原文旁完成搜索、标注、提问、引用核验和知识卡沉淀。

项目不要求云账户，不以订阅、团队协作或托管服务作为成立前提。没有配置 AI 时，阅读、搜索、标注、卡片、备份与恢复仍须完整可用。

## 2. 核心闭环

```text
直接打开本地工作区
→ 导入 PDF / 网页
→ 阅读、搜索、选区和标注
→ 基于授权片段进行 AI 问答
→ 点击引用回到原文
→ 保存知识卡
→ 完整备份并可在新环境恢复
```

## 3. 正式边界

### Reader 负责

- 文档原件、文本、阅读进度和本地索引
- 稳定 Anchor、PDF/网页可视标注、批注编辑删除、书签和原文回跳
- 证据约束的 AI 阅读辅助
- 英文文献全文翻译、原文译文同步对照和连续译文阅读
- 知识卡、专题和可迁移导出
- 完整备份、恢复和离线可用性
- 可审计的本地数据与模型配置边界
- 带签名的桌面安装包、手动更新与可选自动更新
- 阅读模式可收起主导航，并记住用户的阅读布局选择

### Reader 不负责

- 云账号、团队权限和组织后台
- 强制云同步或由项目方托管用户文档
- 学习计划、掌握度建模和课程 Agent 编排

最后一组能力属于 ESA 等上层应用。未来 ESA 可以提供“进入阅读模式”的入口，但两个仓库、数据所有权和发布周期保持独立。

## 4. 交付阶段

### L1：可靠的本地阅读器

- 无登录启动
- 本地 Web 与 Windows Tauri 桌面版
- PDF / 网页阅读闭环
- 引用、标注和知识卡
- 包含 PDF 原件的完整备份与恢复
- 清晰的 AI 降级与本地数据说明
- 开源仓库基线与一键启动

### L2：扩展阅读能力

- EPUB
- 扫描 PDF OCR
- 多文档比较与证据板
- Obsidian / Anki 导出

### L3：高级本地能力

- 操作系统密钥存储
- 可选本地 Embedding、Reranker 和小模型

## 5. 架构约束

- Web 使用 IndexedDB；首个桌面版本复用 WebView IndexedDB 与同一备份格式，后续通过仓储接口迁移大文件到桌面文件系统和 SQLite。
- 桌面版使用 Tauri 2，不捆绑 Node/Next 本地服务器；AI 与网页抓取由 Rust Command 或可替换运行时适配器执行。
- 完整备份必须包含数据库记录与文档原件，并带显式 schema 版本。
- AI Provider 故障不得阻断基础阅读能力。
- 与 ESA 的未来集成通过版本化协议或本地链接完成，不直接读取彼此数据库。
- 任何桌面化改造都应复用领域模型和协议包，不能把 Web UI 变成领域层。
- Desktop 更新失败不得阻塞启动；自动安装必须由用户显式开启，所有更新包必须通过内置公钥验签。

## 6. 性能预算

- 应用框架不等待 AI、PDF 引擎或示例数据，启动后立即可见。
- 普通 Windows 设备冷启动到可交互目标小于 2.5 秒，热启动目标小于 1 秒。
- 不允许用持续超过 300 毫秒的全屏启动页掩盖后台初始化。
- 资料库先显示本地元数据；PDF 引擎、文本提取、AI 和搜索索引按需加载。
- 全文翻译按小段分批执行，每批完成立即持久化；关闭、失败或暂停后不得丢失已生成译文。
- 20 MB 以内普通文本 PDF 的首屏目标小于 1.5 秒；全文提取不得阻塞第一页阅读。
- 自动化验收记录启动阶段与 PDF 首屏时间，性能回退视为发布阻塞问题。

2026-07-31 Windows 验收基线：加入全文翻译后的 release EXE 13.34 MiB，首次启动到可响应窗口约 500 ms，随后启动约 105–108 ms。不同机器允许波动，但不得突破上述目标预算。

## 7. 完成定义

一个新用户无需注册即可在 Web 或桌面版打开 Reader，导入 PDF，完成一次有引用的问答和标注；随后能够导出完整备份、清空本地数据、恢复备份，并继续打开原 PDF 与回跳引用。
